# docs 目录

本目录存放四类文档：单一主题的调研、外部工程分析、本工程自审、实施计划。

| 路径 | 内容 |
|---|---|
| `cloud-stt.md` | 云端语音识别服务调研：国内五家与海外四家的上传方式、分片要求、时长限制、认证方式，末尾给出适配器设想 |
| `external/` | 外部工程分析，每个被调研的工程一份 |
| `audit/` | 本工程自审：`summary.md` 是工程结构、数据流与运行方式的梳理，`risks.md` 是风险清单 |
| `plan/` | 实施计划：一个开发主题一份，写清范围、来源对照、参数出处与验收方式 |

## 外部工程分析

分析外部工程的目的是给本工程开发新模块提供依据，参考它们的做法，判断哪些能力可以移植、哪些依赖在 Python 侧没有对应载体。

现有四份：

- `external/funasr.md`：阿里达摩院语音识别工具箱 `funasr 1.4.15`，能力清单、模型规模、效果数据、接口与部署方式，以及接进本工程语音识别环节的三条路
- `external/downlord.md`：Electron 下载器 DownLord 的下载内核移植到 `src/ihatevideos/download/` 的实施计划，含模块结构、Python 侧技术选择、数据模型、接口、六个交付单元
- `external/course-navigator.md`：视频课程学习工作台 `Liu-Bot24/course-navigator`，字幕与语音识别链路、大模型与提示词体系、ASR 校正工作台、任务框架、桌面壳与分发方式，以及可以借进本工程的十二处做法
- `external/bili-transcript.md`：B 站文稿提取桌面工具 `W1nge/BiliTranscript`，五级字幕降级链、用浏览器承担登录态、多引擎本地识别、局域网提取 API、Windows 原生效果与打包分发，以及可以借进本工程的十二处做法

一篇外部工程分析的写法：开头写明调研对象与方式（仓库路径、版本、只读声明），然后按「它有什么」「数据与结论出自哪个文件」组织，最后写与本工程的结合点与需要决定的事项。效果与性能数字必须标注来源文件与测试条件，二手结论与官方自述要分开写明。

## 实施计划

计划写给本工程的开发者，人类与 Agent 都要能照着做，内容取自外部工程调研或本工程的现状，写到可以逐条执行与验收的程度。

现有两份：

- `external/downlord.md` 第三节起：DownLord 下载内核移植成 `src/ihatevideos/download/` 的六单元总计划，含模块结构、数据模型、接口与三项待决。
- `plan/download-cli.md`：本次要做的下载模块与 `ihatevideos-download` 命令，范围取视频路径与 aria2 直链，含引擎参数逐项抄录、命令行设计、六个交付单元与验收素材。

一篇实施计划的写法：开头写明目标工程、依据材料、本次范围与本机实测环境；正文按范围、模块结构与来源对照、依赖、技术决定、接口、参数、交付单元与验收、验证方式、已知限制、需要拍板的事项组织；参数与数值必须给出出处文件与行号；验收必须写明命令与期望结果，用到的素材要事先确认可用。
